## Rebuilding for the production root

Use the reviewed release source with Node.js 24. For a current production build,
retain the verified GA4 ID introduced after this initial archive and run the
complete checks in the [HostGator release guide](hostgator-release.md):

```sh
npm ci
python3 -B -m unittest discover -s scripts/tests -p 'test_*.py'
env -u PAGES_BASE_PATH -u NEXT_PUBLIC_BASE_PATH \
  -u NEXT_PUBLIC_CALENDAR_AGENDA_URL -u PLAYWRIGHT_BASE_PATH \
  -u PLAYWRIGHT_PREVIEW_ORIGIN -u PREVIEW_BASE_PATH \
  NEXT_PUBLIC_GA_MEASUREMENT_ID=G-6YWHB69NED npm run release:check
npm run calendar:check-public
node scripts/package-hostgator-release.mjs /tmp/laaw-life-release.tar.gz
```

Use a new archive filename for each release. Builds fetch current public
calendar data, so a later build's generated timestamps and archive hash will
differ. The archive hash above identifies the original deployed artifact.

Commit and push every production change before uploading its output files.
